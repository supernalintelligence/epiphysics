This ancillary repair was implemented in managed worktree `date-rendering`, based on `56899ee`, independently of the frozen C11 research-map acceptance work. It changes date presentation only. The supervisor relayed SCI's live finding of React 418 on 55 of 63 pages in `America/Los_Angeles`, compared with zero in UTC. That is an attributed external finding, not a measurement repeated here. This task separately reproduced a concrete source-level cause: the central formatter parses ISO timestamps and reads the host's local calendar fields. `PostComponent`, `FolderListView`, `PostListView` and `BlogCard` use that formatter. `PostCard`, `FeaturedPosts`, search results and timeline grouping used separate locale-default date formatting.

The original central source was retained before editing and executed in separate Node 24.3.0 processes with three explicit timezones. `2026-11-26T00:00:00.000Z` rendered November 26 in UTC but November 25 in Los Angeles. `2026-03-01T00:00:00Z` rendered March 1 in UTC but February 28 in Los Angeles. `2026-11-26T23:30:00Z` rendered November 26 in UTC but November 27 in `Pacific/Kiritimati` (UTC+14). The date-only input `2026-11-26` retained November 26 in all three. These observations establish host-dependent source output; they do not by themselves prove that every reported live hydration failure has this cause.

The repaired shared formatter uses a UTC publication calendar on both server and client. Valid `YYYY-MM-DD` strings retain the stated calendar day, with component validation preventing JavaScript from rolling invalid dates into a later month. ISO timestamps with explicit offsets are converted to UTC; offsetless ISO timestamps are interpreted as UTC. The supported timestamp grammar permits hours/minutes, optional seconds/fraction, and `Z` or a colon-separated numeric offset. Missing values render empty; invalid or unsupported strings remain unchanged rather than being guessed through host-dependent date parsing. Legacy formatter import paths re-export the shared function.

Post cards retain short English month/day/year text; featured cards retain short month/day text; timeline groups retain month/year text. Search results now use the same fixed long English date as article displays instead of the viewer's implicit locale. The preprocessor already serializes publication metadata to ISO timestamps with `toISOString()`, so the unchanged list components' existing intermediate Date objects receive explicit instants. This repair adds no hydration-suppression flag, client-only delay, or date-related dependency.
